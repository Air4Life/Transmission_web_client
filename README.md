# Torrent Harbor 1.1

Торрент-клиент для Ubuntu 24.04 с русским адаптивным веб-интерфейсом.
Движок — системный Transmission 3/4; отдельный экземпляр не меняет настройки
вашего transmission-daemon. Темы: светлая, тёмная, океан, системная.
Внешние CDN, npm и pip для работы не нужны.

## Скачать пакет

Готовый [DEB 1.1.0 можно скачать напрямую](https://raw.githubusercontent.com/Air4Life/Transmission_web_client/main/dist/torrent-harbor_1.1.0_all.deb).
Также он находится в каталоге `dist/`. Исходный код и скрипт сборки находятся в этом репозитории.
Приложение использует отдельный экземпляр transmission-daemon и управляет им через RPC.

## Установка

```sh
sudo apt update
sudo apt install ./torrent-harbor_1.1.0_all.deb
sudo cat /etc/torrent-harbor/config.json
```

Откройте `http://IP-СЕРВЕРА:8080`. Логин `admin`, случайный пароль — в config.json.
Нужны доступные репозитории Ubuntu (для Transmission включите universe).
Пакет Architecture: all подходит для amd64 и arm64 при наличии зависимостей.
Скачанные данные: `/var/lib/torrent-harbor/downloads`.
При включённом UFW разрешите доступ из своей сети, например:

```sh
sudo ufw allow from 192.168.1.1/24 to any port 8080 proto tcp
```

Подставьте свою подсеть. Интерфейс требует пароль и доступен по HTTP без
перенаправления на HTTPS. Браузер запрашивает HTTP Basic авторизацию.

## Keenetic / KeenDNS

Закрепите IP сервера в DHCP Keenetic. В настройках доступа к веб-приложениям
задайте внешний домен/поддомен и внутренний адрес `http://IP-СЕРВЕРА:8080`.
Названия пунктов зависят от KeeneticOS и режима KeenDNS. Внешний HTTPS должен
завершаться на Keenetic/обратном прокси; до приложения остаётся обычный HTTP.
Прокси должен передавать Authorization и не добавлять CORS-заголовки.
Приложение размещается в корне домена, например `https://torrent.example.ru/`,
а не по пути `/torrent/`. Для облачного режима KeenDNS нужна поддержка доступа
к веб-приложениям вашей моделью/прошивкой; прямой режим требует публичного IP.
Обычный проброс внешнего порта на 8080 также работает, но открытый HTTP
передаёт пароль и данные без шифрования: для внешнего доступа используйте HTTPS
Keenetic либо VPN. RPC-порт 9092 наружу открывать не нужно.

Для входящих BitTorrent-соединений при публичном IP можно отдельно пробросить
TCP/UDP 51413. Это другой порт; при CGNAT загрузки через исходящие соединения
работают, но доступность для входящих пиров ограничена.

## Настройки и службы

`/etc/torrent-harbor/config.json`: `listen`, `port`, `username`, `password`.
После изменения: `sudo systemctl restart torrent-harbor`.
Пароль не передаётся сторонним сервисам; конфиг читают root и группа приложения.
Basic авторизация сохраняется браузером до закрытия сессии браузера.

```sh
systemctl status torrent-harbor torrent-harbor-engine
journalctl -u torrent-harbor -u torrent-harbor-engine -n 100
```

Настройки движка: `/var/lib/torrent-harbor/engine/settings.json`. Сначала
остановите `torrent-harbor-engine`, измените файл, затем запустите службу.
Не меняйте локальные RPC адрес и порт без изменения server.py.
Произвольная папка загрузки должна быть доступна пользователю `torrent-harbor`
на запись и поиск по родительским каталогам. Веб-служба не читает файлы загрузок;
их скачивает движок. В «Настройках» доступны папки, лимиты скорости, очереди, рейтинг отдачи,
параметры пиров и шифрования. Настройки применяются через RPC без рестарта и
сохраняются самим Transmission. Не редактируйте settings.json при работающем
движке: при остановке он перезапишет ручные изменения.

Нажмите название торрента, чтобы выбрать файлы и задать приоритет: низкий,
обычный или высокий. Нажмите «Сохранить выбор». Для magnet дождитесь получения
метаданных; можно нажать «Обновить список». Для выбора до загрузки данных
добавьте .torrent на паузе, настройте файлы и затем запустите его. У magnet
метаданные обычно получаются после запуска; часть данных может успеть загрузиться.
Пропуск файлов не удаляет уже скачанное. BitTorrent скачивает данные блоками:
небольшие части пропущенных файлов на границах блоков могут быть загружены.

## Удаление и обновление

`sudo apt remove torrent-harbor` останавливает обе службы. Загрузки, пароль и
состояние сохраняются, включая purge. Обновление через `apt install ./...deb`
сохраняет настройки. Для окончательной очистки удалите каталоги вручную только
после резервного копирования нужных данных.

## Сборка и проверки

```sh
./build-deb.sh
python3 -m unittest discover -s tests -v
```

Сборка требует dpkg-deb и стандартные GNU coreutils. Результат в `dist/`.
Пакет не включает бинарник Transmission: apt устанавливает его из Ubuntu.

## Обновление с 1.0.0 до 1.1.0

```sh
sudo apt install ./torrent-harbor_1.1.0_all.deb
```

Обновление перезапустит службы; пароль, настройки, торренты и файлы сохраняются.
Обновите страницу браузера. Откройте «Настройки», чтобы задать папки и другие
параметры. Откройте «Файлы» у нужного торрента для выбора и приоритетов.
Пароль веб-интерфейса и HTTP-порт по-прежнему задаются в config.json.

Проверки 1.1.0: 8 серверных тестов, сценарии Chromium на desktop/mobile с
имитацией RPC Transmission (настройки, выбор файлов, приоритеты, ошибка
сохранения и повтор, ожидание метаданных). Проверка с реальным демоном и
установка на Ubuntu 24.04 в среде сборки не выполнялись.
