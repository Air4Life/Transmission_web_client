# Torrent Harbor 1.2.1

Русский адаптивный веб-интерфейс для Ubuntu 24.04 на движке Transmission.
Отдельный экземпляр `transmission-daemon`, темы, HTTP-доступ и DEB-пакет.

[Скачать DEB 1.2.1](https://raw.githubusercontent.com/Air4Life/Transmission_web_client/main/dist/torrent-harbor_1.2.1_all.deb)

## Установка и обновление

```sh
sudo apt update
sudo apt install ./torrent-harbor_1.2.1_all.deb
sudo cat /etc/torrent-harbor/config.json
```

Откройте `http://IP-СЕРВЕРА:8080`. Войдите через страницу авторизации:
логин `admin`, случайный пароль указан в конфиге. Старая авторизация HTTP Basic
больше не используется. После обновления обновите страницу браузера.
Обновление перезапускает службы, сохраняет пароль, торренты, настройки и данные.
Ubuntu устанавливает зависимости из своих репозиториев; требуется universe.
Architecture: all — amd64/arm64 при доступных системных зависимостях.

## Выбор папки на сервере (1.2.1)

Нажмите «Папка» у торрента → «Выбрать папку…». В окне можно открывать
каталоги сервера, переходить вверх и по частям пути, искать подкаталоги,
показывать скрытые папки. Большие списки подгружаются кнопкой «Показать ещё».
Нажмите «Выбрать эту папку», затем «Применить» в окне переноса. Выбор папки
сам по себе не перемещает файлы. Ручной ввод пути также доступен.

Это папки Ubuntu-сервера, а не компьютера, с которого открыт браузер.
Список видит только вошедший администратор, с правами системного пользователя
`torrent-harbor`. Каталоги без доступа нельзя открыть. При выборе проверяется
фактический доступ на запись (или чтение для поиска уже перенесённых файлов).

## Возможности 1.2

- Предпросмотр `.torrent` до добавления: отметки файлов, размеры и приоритеты.
- Magnet: отдельное получение только метаданных, затем выбор файлов и запуск.
  `python3-libtorrent` используется только для предпросмотра; скачивает и раздаёт
  файлы Transmission. Resolver работает с флагом `upload_mode`, не запрашивая
  блоки содержимого. Предел ожидания 90 секунд, до двух параллельных задач.
  «Отмена» завершает получение метаданных. Предпросмотр истекает через 10 минут.
- Кнопка «Папка» у торрента: переместить файлы или указать, где они уже лежат.
  Во втором случае запускается проверка. Выберите родительскую папку каталога
  многофайлового торрента. Сам перенос выполняет Transmission; крупные данные
  переносятся не мгновенно. Проверяйте итоговый путь и сообщения об ошибках.
- Проверка существования папки, прав на чтение/запись и свободного места.
  Проверяется реальное создание и удаление временного файла от пользователя
  `torrent-harbor` в отдельной службе с ограничениями движка. Веб-служба не
  получает запись в произвольные каталоги. Папки автоматически не создаются.
- Страница входа, выход с отзывом сессии, cookie HttpOnly/SameSite=Strict,
  CSRF-токены. Сессия действует 12 часов и сбрасывается после рестарта веб-службы.
  После пяти неудачных входов с одного адреса — блокировка до конца пятиминутного
  окна. Адрес определяется по TCP-соединению; заголовки X-Forwarded-For не
  используются. За Keenetic пользователи одного прокси могут делить этот лимит.

Предпросмотр не добавляет торрент в Transmission. Только после подтверждения
сервер добавляет его на паузе с выбором файлов/приоритетов и затем запускает,
если не выбрано «Оставить на паузе». Дубликат не изменяет существующий торрент.
Снятие отметок не удаляет уже скачанное. На границах BitTorrent-блоков могут
скачиваться небольшие части невыбранных файлов. Для добавления нужен хотя бы
один выбранный файл. Метаданные magnet требуют доступных пиров/DHT и сети.

Настройки папок, скорости, очередей, раздачи и пиров меняются в «Настройках»
через RPC. Transmission сохраняет их сам. Новая папка по умолчанию применяется
к новым торрентам; существующие переносите кнопкой «Папка».
При нехватке места добавление блокируется по сумме выбранных файлов; это
предварительная проверка, а не резервирование дискового пространства.
Служба проверки и движок разделяют временную директорию systemd; веб-служба
изолирована. Папки внутри `/etc`, `/usr`, `/boot` ограничены движком systemd.

## Папки и права

Загрузки по умолчанию: `/var/lib/torrent-harbor/downloads`.
Для отдельного каталога, например:

```sh
sudo mkdir -p /mnt/downloads
sudo chown torrent-harbor:torrent-harbor /mnt/downloads
```

Родительские каталоги должны разрешать проход пользователю `torrent-harbor`.
Для уже используемых общих папок настройте группу или ACL, не меняя владельца
всего существующего дерева. Кнопка проверки покажет ошибку и доступное место.

## Keenetic / KeenDNS

Закрепите IP сервера в DHCP. В доступе к веб-приложениям Keenetic укажите
внутренний адрес `http://IP-СЕРВЕРА:8080` и внешний домен, например
`https://torrent.example.ru/`. Приложение размещается в корне отдельного домена,
а не под путём `/torrent/`. Названия пунктов зависят от KeeneticOS/модели.
Keenetic завершает внешний HTTPS, до приложения остаётся обычный HTTP.
Прокси должен передавать Cookie и Set-Cookie без добавления CORS-заголовков.

Внутренний HTTP поддерживается без принудительного HTTPS. Для внешнего доступа
используйте HTTPS Keenetic либо VPN: обычный HTTP передаёт пароль и cookie без
шифрования. Если пользуетесь только внешним HTTPS, добавьте `"secure_cookie": true`
в config.json; после этого вход через обычный HTTP по IP работать не будет.
По умолчанию Secure выключен для запрошенного доступа по HTTP во внутренней сети.
Облачный режим KeenDNS зависит от поддержки веб-приложений моделью/прошивкой;
прямому режиму нужен публичный IP.

При включённом UFW разрешите свою подсеть, например:

```sh
sudo ufw allow from 192.168.1.0/24 to any port 8080 proto tcp
```

RPC 9092 слушает только localhost; не пробрасывайте его наружу.
Для входящих пиров можно отдельно пробросить TCP/UDP 51413 при публичном IP.

## Службы и конфигурация

`/etc/torrent-harbor/config.json`: listen, port, username, password,
необязательный secure_cookie. После изменения:

```sh
sudo systemctl restart torrent-harbor
systemctl status torrent-harbor torrent-harbor-engine torrent-harbor-paths
journalctl -u torrent-harbor -u torrent-harbor-engine -u torrent-harbor-paths -n 100
```

Настройки движка: `/var/lib/torrent-harbor/engine/settings.json`.
Для ручной правки сначала остановите `torrent-harbor-engine`, иначе при выходе
Transmission перезапишет изменения из памяти. Предпочитайте веб-настройки.
Случайные пароли пользователей и сессии не входят в исходники или пакет.
Удаление через `sudo apt remove torrent-harbor` останавливает службы; загрузки,
настройки и пароль сохраняются, включая purge. Окончательно удаляйте каталоги
только вручную после сохранения нужных файлов.

## Сборка и проверка

```sh
./build-deb.sh
python3 -m unittest discover -s tests -v
# Проверки в изолированном Ubuntu 24.04 (требуется Docker):
./tests/ubuntu/run.sh
```

Для браузерной проверки нужны Node, Playwright и Chromium:
`node tests/browser.cjs` (путь браузера `/usr/bin/chromium`).
Приложению Node/npm/pip не требуются. Пакет зависит от python3, python3-libtorrent,
transmission-daemon, adduser и systemd.

В `.github/workflows/ubuntu.yml` настроена автоматическая сборка и проверка
на Ubuntu 24.04 с настоящими systemd и Transmission: установка 1.1.0,
обновление до 1.2.1, права папок, предпросмотр, выбор файлов и приоритетов,
физический перенос/поиск данных, magnet с локальным пиром, сохранение после
рестарта и удаление без потери данных. Docker-версия запускает процессы
вручную и отдельно проверяет синтаксис unit-файлов.
